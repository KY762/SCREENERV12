## 1. The question, and the tension that produced it

A session on 2026-10-03 flagged an inconsistency in `docs/09-REJECTED.md`
(lines 170-175). It calls H5 "never given a fair test" and separately claims:

> "The indicator it rests on is the strongest thing measured here (IC +0.033
> at 20 days, 59% positive), so the idea survives even though this
> specification does not."

The open question was factual: **was the IC +0.033 measured on the same
variable the battery actually ranked on?** It was not. Two different
functions, confirmed by file and line:

- **The IC.** `research/ic-development.txt` and `research/ic-tail-largecap.txt`
  (2026-09-22, `sp500_pit`, 2010-2015, 1,020 symbols) record `ret(252) skip 21`
  at `IC +0.0334, t +1.65, 59% positive` at the 20-day horizon -- the exact
  figure docs/09 quotes. That family is built in `cli.py:1215-1217`
  (`diagnose predictive`):

  ```python
  families["ret(252) skip 21"] = {
      t: ind.returns(b["close"], 252).shift(21)
      for t, b in bars_by_symbol.items() if t != "SPY" and not b.empty
  }
  ```

  `ind.returns(close, 252)` is a plain trailing return with no volatility
  division; `.shift(21)` lags it a month. This is the RAW variable.

- **The battery.** `h5_momentum_canonical` (`src/screener/research/battery.py`
  lines 285-291) is the experiment that scored the 0th percentile on the
  2026-09-20 battery (`research/20260920-development-battery.md` line 35) --
  the exact run docs/09 cites as "this specification". Its hypothesis, `h5`,
  dispatches in `backtest/runner.py` lines 341-346 to
  `canonical_momentum_candidates`, which (`backtest/strategies.py`, before
  this file's own change) scored every candidate with:

  ```python
  scores[ticker] = volatility_scaled_momentum(
      bars["close"], lookback, skip, vol_window
  )
  ```

  `volatility_scaled_momentum` (`calc/momentum.py`) is `momentum_skip`
  **divided by trailing realized volatility** -- a different variable, by the
  module's own docstring ("an unscaled ranking is partly a volatility
  ranking"). Every other H5 battery arm (`h5_skip_matters`, `h5_no_stop`,
  `h5_rebalance`, `h5_exit_isolated`) goes through the same dispatch and
  therefore the same scaled scoring function; none of them ever ranked on the
  raw variable either.

**The tension is real, not a false alarm.** The IC that makes the case for
retesting H5 and the specification that was actually battery-tested are two
different variables. Neither has been fairly measured against the other, so
H10 tests the one the IC claim actually rests on: raw `momentum_skip`
(`lookback=252, skip=21`), with everything else held at
`h5_momentum_canonical`'s own values.

### What is NOT new evidence here, and has to be weighed honestly

The raw variable has already been traded, once, as part of a different
strategy. `docs/10-SWING-STRATEGY.md`'s `RANK` line is explicitly "raw
12-month return... NOT volatility-adjusted" -- the same `ret(252) skip 21`.
Bundled with `swing_small_mid` (US mid/small caps, not `sp500_pit`), an
SMA50>SMA200 trend filter, a 3xATR trailing stop with no target, and 0.5%
risk at 10 positions, it scored the **0.1st percentile**, below random in all
three regimes, p = 0.9990 -- a more decisive failure than any scaled H5 arm
has produced. docs/10 also reports the mechanism directly: on the small-cap
universe, raw momentum's tail lift is high (2.04x, t = +9.91) but "concentrates
both tails" -- it finds the biggest losers as reliably as the biggest winners,
so a convex rule built on it nets nothing.

That result does not settle H10, for two reasons stated plainly rather than
argued around:

1. **Different universe.** The IC +0.033 was measured on `sp500_pit`
   (large-cap, point-in-time). docs/10's trade-level test was run on
   `swing_small_mid`. Higher-volatility small/mid caps are exactly where
   dividing by volatility matters most (that is the entire argument for
   `volatility_scaled_momentum` existing); whether raw momentum's tails stay
   symmetric on a lower-volatility large-cap pool is the part that has not
   been measured.
2. **Different package.** docs/10 adds a trend filter and a specific
   trailing-stop/no-target exit on top of the raw ranking, which is the
   whole-strategy bundling this project has repeatedly found hides which part
   failed (docs/09 "Strategy" section; the reason `*_exit_isolated` arms
   exist at all). H10 isolates the ranking variable alone, against H5's own
   harness, so a failure or a pass is attributable to the one thing that
   changed.

**Prior expectation, stated before looking:** docs/10's result is strong,
directly relevant prior evidence that raw momentum's tail behavior does not
survive contact with a real portfolio, and it should be weighed as such
regardless of what H10 shows. H10 is not expected to succeed; it is run
because the specific large-cap/isolated-ranking question has not actually
been asked, and docs/09's "the idea survives" claim should not stand
unchecked when it does not currently rest on the thing that was tested.

## 2. The configuration

**Code.** `canonical_momentum_candidates` (`backtest/strategies.py`) gains a
`scaled: bool = True` parameter. Default True reproduces H5's existing
behaviour exactly (pinned by
`test_scaled_defaults_true_and_changes_nothing_about_h5`); `scaled=False`
scores on `momentum_skip` instead of `volatility_scaled_momentum`
(`test_scaled_false_ranks_on_raw_momentum_not_volatility_adjusted` pins that
the switch actually changes the ranking, not just the flag). H10 is NOT added
to `backtest/runner.py`'s `HYPOTHESES` tuple or to `BATTERY` -- the same
choice already made for H8 and H9, which run through their own diagnostics
rather than the H1-H7 `RunConfig`/battery machinery, so adding H10 cannot
collide with or silently extend any pinned test or shared default built for
H1-H7.

**Command.** `screener diagnose raw-momentum --universe sp500_pit --split
development` (`cli.py`, `diag_app.command("raw-momentum")`). It is development-
split only; it refuses to run on an evidential split outright, the same way
`backtest surface` does.

**Grid -- identical to `h5_momentum_canonical`
(`src/screener/research/battery.py` lines 283-291), changing only the scoring
function:**

## 3. What passes on development

Written before `screener diagnose raw-momentum` has been run.

1. The 3x3 surface (docs/03 section 0.7) returns **plateau** or **separated**,
   not spike or none. A spike or a none is evidence against H10 outright, per
   the same rule already applied to every other surface in this project --
   not an invitation to widen the grid.
2. If it does, the selected cell (plateau centre, or the separated winner)
   clears **all six** of `backtest/performance.py`'s pre-registered criteria,
   unchanged from every other hypothesis in this project:
   - `trade_count`: >= 200 effective observations
   - `expectancy`: > 0R
   - `profit_factor`: > 1.20
   - `max_drawdown`: < 25%
   - `regime_robustness`: beats random in >= 2 of the split's 3 regime
     buckets, no bucket worse than -15%
   - `vs_random`: same-day (date-matched) one-sided p <= 0.05

Both conditions, together. Failing either is a fail; this is a single
development look, so Holm's correction does not apply here (no family exists
on development), but it will if a validation configuration is ever proposed
from this file.
