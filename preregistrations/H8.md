## 1. The question

Does leaving out the pool's most volatile fifth and the fifth with the
largest one-day gain in the past month make a random pick from what remains
beat a random pick from everything? Full reasoning and evidence: docs/11.

## 2. The configuration

docs/11 section 2, unchanged:

```
POOL        swing_small_mid, point-in-time, as built
SCREEN      leave out the pool's top 20% on the date by EITHER
              vol60   standard deviation of daily returns, 60 sessions
              max21   largest daily return, 21 sessions
HORIZON     20 sessions, windows 20 sessions apart (no overlap)
TRADE       the engine's rules (docs/11 section 2)
COST        each name's own measured spread
STATISTIC   per window, mean net return of the screened pool minus the full
            pool's; mean of that across windows, and its t
```

This is a *diagnostic* configuration (`kind = "diagnose_screen"` below), not a
`backtest run` configuration -- it has no hold, stop, or entry rule of its
own to tune. `pool` and `horizon` are the only two dimensions `screener
diagnose screen` exposes as options today; `vol_window`, `max_window` and
`screen_quantile` are written out explicitly below so this registration's
hash does not depend on `diagnostics/screen.py`'s own constants moving later
-- the same reason H1's file writes out `hold` explicitly (see H1.md section
8... actually section on "the hold is written out explicitly").

## 3. What passes if signed and run

Per docs/11 section 4, "to pass validation": the net statistic at one-sided
p <= 0.05 **after Holm** across the registered validation family, and
positive in at least 2 of the split's 3 regime buckets (bull_2017,
correction_2018q4, bull_2019). **`screener diagnose screen` does not compute
the Holm-corrected verdict itself** -- it prints the raw statistic and
records it in `research_runs`; the Holm step is read by hand against
`screener prereg family`, same as every other hypothesis.

## 4. What this spends

One of H8's 3 validation configurations (docs/11 decision 4: H8 is its own
hypothesis with its own budget, and joins Holm's family on this split).

## 5. Before signing

- Holm's family must be closed first (the same precondition every other
  hypothesis's file names): signing this after other validation runs on this
  split have already happened changes the bar they were held to.
- This file being loadable and the budget machinery existing does not make
  running it a good idea by itself -- docs/11 section 5 is explicit that the
  development result "earns a validation run under §4; it is not evidence
  that the screen works," and about a third of the net figure is mechanical
  (spread saved, not statistical).
